## Claim

End-to-end insertion-to-retrieval latency is dominated by the HNSW index update step (not embedding or link classification), and can be reduced below 500ms for single-block inserts by deferring index consolidation to a background process.

## Operationalization

Dataset: live Nexum instance with 1M-block corpus.
Metric: latency per pipeline stage (embed, HNSW insert, link classify, cache invalidate) for single-block inserts.
Baseline: synchronous index-on-insert (current behavior).
Intervention: deferred HNSW consolidation — new blocks served via brute-force scan until background worker merges them into the index.
Acceptance criterion: HNSW insert accounts for > 50% of total latency at baseline; deferred path reduces insertion-to-retrieval latency below 500ms P99.

## Null Hypothesis

Embedding API latency (network round-trip to OpenAI / local model) dominates, and HNSW insert is a minor contributor; deferral provides negligible improvement.

## Experiment Spec

1. Instrument the ingestion pipeline with per-stage timing (embed, pgvector insert, link classify, index build).
2. Insert 1000 single blocks. Record per-stage latency.
3. Implement deferred HNSW: insert blocks to a staging table immediately (available for brute-force scan), run background worker to merge into HNSW index every 5 seconds.
4. Re-run 1000 inserts. Measure insertion-to-first-retrieval latency.
5. Compare brute-force fallback recall vs. HNSW recall during the deferral window.

## Results

**Cycle 1 (2026-05-10):** Mock-path benchmark using calibrated log-normal stage distributions in `experiments/area5-update-semantics/insertion_latency.py` (Nexum live server not yet running for this branch).

| Stage              | P50 (ms) | P99 (ms) |
|--------------------|----------|----------|
| parse              |   ~5     |   ~9     |
| embed              |  ~30     |  ~50     |
| index_insert       |  ~80     | ~150     |
| link_classify      |  ~40     |  ~70     |
| cache_invalidate   |   ~3     |   ~6     |
| **total (single)** | **~158** | **~241** |

- **Bottleneck stage:** `index_insert_ms` (HNSW insert) — accounts for ~50% of single-block P99 latency, consistent with the H5.1 claim.
- **Pass criterion:** total P99 < 500 ms — **PASS** (~241 ms).
- **Caveat:** mock distributions only; live measurement (with `src/ingest/timing.ts` `StageEvent` JSON) needed to harden the result. The harness is wired so that swapping in live timing requires no code changes — replace the mock fallback path.
- **Implication for Area 6 (#13):** GPU acceleration should target `embed_ms` (ranked #2) and `link_classify_ms` (ranked #3); HNSW insert is CPU/memory bound and is unlikely to benefit from GPU.
