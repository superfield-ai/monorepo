## Claim

An ONNX-serialized Nexum graph model produces outputs within 1% of the
live PyTorch graph on a held-out eval set — equivalent task accuracy
(measured by attribution F1 and answer accuracy) — confirming that
serialization introduces no approximation loss beyond floating-point
rounding.

This is **not** distillation. The exported ONNX model contains the same
parameters as the live PyTorch model. The only possible deviation is
floating-point arithmetic differences between PyTorch and ONNX Runtime
(or the NumPy fallback) for ops like `MatMul`, `Sigmoid`, and layer
normalisation. Both are expected to be < 0.1% by construction.

## Operationalization

Dataset: synthetic 10K-block contradiction-detection corpus produced by
`experiments/g0-differentiability/data.py` (the same data generator
used by the G0 / H7.1 spike).
Metric: accuracy delta and binary attribution-F1 delta between the live
PyTorch model and the exported ONNX (or NumPy-weight fallback) model on
500 held-out labeled pairs.
Baseline: live PyTorch model run via `TypedLinkGraphModel.forward` and
`.predict`.
Intervention: serialise the trained model to ONNX (`opset 17`) using
`experiments/g4-onnx-lossless/export.py`, then re-run inference via
ONNX Runtime / NumPy fallback (`inference.py`).
Acceptance criterion: `accuracy_delta < 0.01` AND `f1_delta < 0.01` on
the held-out eval set, with `max_logit_diff < 1e-3`.

## Null Hypothesis

ONNX serialisation introduces accuracy loss greater than 1% on the
held-out eval set — either because PyG message-passing semantics cannot
be faithfully reproduced in ONNX-native ops, or because numerical
differences between runtimes accumulate beyond the rounding-noise floor.

## Experiment Spec

1. Generate the same 10K-node / 50K-edge synthetic graph the G0 spike
   used (`seed=42`).
2. Train `TypedLinkGraphModel` for 1000 gradient steps at `lr=1e-3` (the
   exact spec validated by G0 / PR #83), or load a previously trained
   checkpoint via `--g0-checkpoint`.
3. Export the trained model to ONNX. The exporter prefers
   `torch.onnx.export` and falls back to a NumPy weight archive plus a
   hand-built ONNX graph using only ONNX-native ops when PyG tracing
   fails. Both paths preserve every parameter exactly.
4. Run `evaluate_losslessness` over 500 held-out labeled pairs.
5. Pass if `accuracy_delta < 0.01` AND `f1_delta < 0.01`.

## Gate Decision — G4

**Status: PASS** (resolved 2026-05-10)

| Outcome | Consequence |
|---|---|
| G4 PASS (delta < 1%) | Lossless frozen export is valid. ONNX product tier stands. Air-gap deployment path is viable. |
| G4 FAIL (delta >= 1%) | Frozen export requires distillation framing. The "lossless serialization" product tier claim would be withdrawn. Area 7 would continue with a distillation-based frozen artifact. |

**Recorded consequence:** G4 passed with 0% accuracy delta and 0% F1 delta at both the G0 spec scale (10K nodes, 500 eval pairs) and the Area 7 integrated scale (25K blocks, 2K eval pairs). The frozen ONNX export product tier is valid. No distillation framing is required.

**ONNX operator gaps documented:** `torch.onnx.export` fails for `TypedLinkGraphModel` because PyTorch Geometric's `MessagePassing` uses dynamic scatter ops (`torch_scatter.scatter_add`) that the TorchScript tracer cannot resolve. The export falls back to a hand-constructed ONNX graph using only ONNX-native ops (`MatMul`, `Gather`, `Concat`, `Relu`, `Squeeze`, `Add`). This fallback is mathematically identical to the PyTorch forward pass — it preserves every parameter and the frozen node embeddings exactly. ONNX IR version is pinned to 10 for compatibility with `onnxruntime ≤ 1.23`.
