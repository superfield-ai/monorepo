## Claim

Embedding storage dominates total DB size (> 70%) at 1536 dimensions, making quantization (int8 / binary) the most impactful optimization lever for single-institution deployments.

## Operationalization

Dataset: existing Nexum schema at 1M blocks.
Metric: bytes per component (embedding column, text content, link table, metadata).
Baseline: full float32 1536-dim vectors.
Intervention: int8 quantization (pgvector scalar quantization), binary quantization.
Acceptance criterion: embedding column accounts for > 70% of total table size at float32; int8 quantization reduces total DB size by > 40% with recall@10 degradation < 3%.

## Null Hypothesis

Text content or link metadata dominates storage; quantization provides marginal total-size improvement.

## Experiment Spec

1. Insert 1M blocks into the Nexum schema with float32 embeddings.
2. Run `pg_size_pretty` and `pg_column_size` to measure per-column storage breakdown.
3. Recreate the table with int8-quantized embeddings (pgvector `halfvec` or scalar quantization).
4. Measure size reduction.
5. Run 1000 ANN queries on both and compare recall@10 against exact brute-force results.
